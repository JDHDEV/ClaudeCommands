## 2. Strategic Assessment

*(Source: tech-lead agent. Verdict: **proceed, with reshaping**.)*

- **Right feature, with a dead-weight risk.** Tasks 1 and 3 fill a real, documented gap: `IntialPlan.md:34` asks for per-invocation routing and no skill passes a per-spawn `model` or `effort` today (CONFIRMED by grep: the only `model` hit in `skills/Fable-5` is `disable-model-invocation`). A Taskmaster nothing calls is dead weight. That changes the **design**, not the scope: Taskmaster takes a **batch** of planned spawns (1..N) and returns one structured route per spawn, so wiring it in later is a copy-paste step; `workflow-author` is named as the first in-scope caller; `guide.md` shows direct invocation.
- **Router economics.** Every Taskmaster call is a spawn on the critical path before the fan-out it routes. It only pays off if it is much cheaper than what it routes: batch mode, `sonnet` (not fable or opus), the target agent's frontmatter model as the baseline, and a caller-side skip rule (do not route pinned stages, SendMessage continuations, fewer than about 3 spawns with no runtime-varying difficulty, or Taskmaster itself).
- **Riskiest part: Task 2's open-ended "enhance each agent".** No validator checks prompt quality, only structure. The specific trap is tools: the catalog calls security-auditor's job "Dependency scanning", which invites adding Bash and would weaken its read-only guarantee. Mitigation adopted: the per-agent change matrix in §7.1, with tools, model, mode, and contract heading frozen.
- **Second risk: safety floors.** A cost-minimizing router could quietly send adversarial-verifier or security-auditor to haiku. Hard floors and "task text can only raise, never lower" are written into the Taskmaster prompt (§5.1).
- **Leverage:** the §1.1 tier table as the rubric seed; each agent's frontmatter `model` as the baseline; `agents/Fable-5/workflow-author.md` as the structural template for `taskmaster.md`; the validators are already parameterized, so the fork costs two path-string edits.
- **Avoid:** a shared "current version" variable across scripts (two literals is the minimum); a "use PROACTIVELY" description on Taskmaster (would auto-delegate every spawn); putting effort guidance inside agent bodies as if the agent could set its own effort (the caller sets it).
- **Sequencing:** freeze and fork. The Fable-5 restructure is staged but **uncommitted** (CONFIRMED). The frozen snapshot only exists in history once committed, so the executor asks the user to commit it first (user's decision, never the plan's).
- **Naming.** "taskmaster" suggests task decomposition and collides in people's minds with the third-party `claude-task-master` plugin (namespaced, so no hard collision). The user chose the name; the description opens with "Model router" so neither humans nor auto-delegation confuse it.

### 3.2 Conventions every new or edited agent file must follow

- Frontmatter between `---` fences, keys in this order and **no others**: `name`, `description`, `tools`, `model`. `name` equals the lowercase kebab-case filename stem. `tools` is a YAML block list and must be non-empty. `model` is one of `haiku|sonnet|opus|fable|inherit`.
- `description` is a delegation trigger ("what it does + when to use it"), single-line, double-quoted, and says "Read-only" where true. Never "proactively" / "MUST BE USED".
- Body order: role paragraph, `## Rules`, one domain section, `## Output Format`, Fable-era sections, and `## Subagent Contract` **last** (validator requires the heading), stating `Mode: fire-and-forget` or `Mode: persistent`.
- Read-only agents never hold `Write`/`Edit`. Read-only agents that hold Bash (adversarial-verifier, release-manager) carry a "Bash-despite-read-only (accepted tension)" clause.
- Files are self-contained and portable: a prompt embeds any rubric it needs (Taskmaster embeds the tier table) instead of linking to `IntialPlan.md`.
- Files are UTF-8 **without BOM**. Write content with the Write/Edit tools; mirror with `Copy-Item`; never round-trip through PowerShell 5.1 `Set-Content -Encoding UTF8` (adds a BOM and breaks the opening fence).
- Edit canonical first, mirror last, run all four validators.

## 5. Design

### Approach

Freeze and fork, then add the router. (1) Commit the pending Fable-5 restructure (user's decision). (2) Copy `agents/Fable-5/*.md` byte-for-byte to `agents/Fable-5.1/`, and while content is identical flip both validator path literals and add `taskmaster` + `release-manager` to `$ReadOnlyAgents`. (3) Apply the §7.1 change matrix to the 15 copies, mirroring and validating after each, then the X-1/X-2 pass. (4) Write `taskmaster.md` from the spec below, cross-check it against the Insert A text now in `IntialPlan.md`, mirror, validate. (5) Update `CLAUDE.md`, `guide.md`. (6) Parity proof, frozen-snapshot proof, smoke suite, roadmap closure, four validators.

### Architecture

```
IntialPlan.md §1.1 tier table  ──(embedded copy, keep in sync)──▶  agents/Fable-5.1/taskmaster.md
                                                                          │  reads only `^model:` of
                                                                          ▼
orchestrator (skill main session / Workflow pre-stage)  ──spawn set──▶  taskmaster  ──routes JSON──▶  orchestrator clamps ──▶ Agent tool `model` / agent() opts.model+opts.effort
                                                                          ▲
                                                .claude/agents/<agent>.md (live install, mirrors agents/Fable-5.1/)

agents/Fable-5/   (frozen snapshot, git-guarded)   agents/Fable-5.1/  (canonical, validated)   .claude/agents/  (mirror, validated)
```

Validators: `validate-agents.ps1` default canonical = `agents/Fable-5.1`; `validate-skills.ps1` phantom-agent allowlist = stems of `agents/Fable-5.1/*.md` (so `taskmaster` becomes a legal `subagent_type` automatically).

### Key Decisions

See §3.5. Three further decisions made by the planning lead:

1. **Adopt the strict exact-tool-set rule for taskmaster** (SEC-04) even though the synthesis marked it optional. The validator is this repo's unit test and Taskmaster's entire safety story is its tool set; the cost is about five lines plus three fixture cases.
2. **Adopt two cross-cutting one-sentence enhancements for all 16 agents** (X-1 untrusted-content rule, SEC-13; X-2 caller-schema precedence, which four per-agent reviews proposed independently). The exact sentences are fixed in §7.1 so presence can be counted mechanically.
3. **Cut `stands_in_for`, `prior_attempts`, and independent effort routing from v1** after the completeness review (speculative; no consumer; they introduced a name-pattern bug and non-deterministic golden cases).
